# 版本与出口控制

Hrules 当前 Mihomo 公共产品分为 **标准版 Standard** 与 **精细版 Fine-grained**。

这两个版本不是安全等级。它们共享同一套 Hrules Core 和规则文件，区别是：**同一批已识别请求最终向用户暴露多少独立的场景出口控制点。**

## 🟢 标准版 Standard

面向公开实用，减少需要手动管理的策略组。

界面场景：

`🌐 海外应用 → 📺 流媒体 → 🤖 AI 服务 → 💳 金融服务 → 🚀 漏网之鱼`

银行、券商、支付 / 跨境金融、虚拟货币统一映射到金融服务；YouTube、Telegram、普通国际应用以及标准版 Apple / iCloud 映射到海外应用。

## 🔵 精细版 Fine-grained

面向需要更细独立出口控制的用户，也用于展示 Hrules 的业务分类能力。

界面场景：

`🌐 海外应用 → 📺 流媒体 → 🤖 AI 服务 → 🍎 Apple / iCloud → 🏦 银行服务 → 📈 证券 / 券商 → 💳 支付 / 跨境金融 → 💰 虚拟货币 → 🚀 漏网之鱼`

精细版不拆分 AI；主要增加 Apple / iCloud 与金融业务的独立出口控制点。

## 出口控制原则

在能够读取真实节点的 Mihomo 接入中：

- **选择地区**：自动选择只发生在该地区已有节点内部，不跨地区漂移。
- **选择具体节点**：该场景固定使用所选节点。
- **机场原有策略组**：继续保留，Hrules 不删除宿主已有的自动选择、故障转移或负载均衡组。
- **漏网之鱼**：承接最终未命中前置 Hrules 场景规则的流量。

Clash Verge Rev 的订阅扩展脚本与 3X-UI Remote Routing 已分别按其接入方式读取真实节点。其他 Mihomo / Clash Meta 客户端是否能提供相同的节点级控制，取决于客户端实际支持的配置入口，必须完成对应客户端验证后再声明支持。

精细版当前继续沿用原 `hrules-strict.js` / `hrules-strict.yaml` 文件名，以保持既有 Raw URL 兼容。

> Hrules 负责路由识别与出口选择，不保证第三方服务不会触发风控、账号审核、封禁或地区资格限制。
