# 路由模式

Hrules 将出口选择方式分为三档：**标准、稳定、严格**。

这里的分类用于帮助用户理解路由行为，不要求用户接受任何“敏感度”标签。

## 🟢 标准

目标：**可用性与日常体验优先**。

允许使用自动选择、常规故障转移等方式，在节点变化时优先保证服务继续可用。

典型场景：普通海外网站、YouTube、一般网络服务。

## 🟡 稳定

目标：**尽量保持地区一致**。

当首选出口不可用时，优先在同一地区内选择其他可用出口，减少服务会话过程中地区发生变化。

典型场景：AI 服务以及其他对地区一致性有一定要求的服务。

## 🔴 严格

目标：**出口更加明确和可预测**。

限制不受控的自动漂移。用户应明确知道场景最终允许使用哪些出口；需要故障切换时，也应在预先允许的范围内进行。

典型场景：银行、券商、Crypto、重要账户等需要更谨慎管理出口的场景。

## 模式与场景是两个维度

场景回答：

\`这是什么流量？\`

路由模式回答：

\`这类流量允许怎样选择出口？\`

上述“同地区故障转移”“受限出口”等是 **Edition 的目标语义**，实际可用能力取决于接入方式能看到的节点清单：

- 完整 YAML / full-config transformation：可以读取具体 \`proxies\`，可实现节点级地区组、同地区故障转移和具体节点绑定。
- Clash Verge Rev Global Extension Script：只有当前配置暴露具体 \`proxies\` 时才能提供节点级能力；仅有 \`proxy-providers\` 时无法枚举 Provider 运行时节点，Strict 不应作为支持路径使用。
- 3X-UI Remote Routing：只安全绑定宿主 \`PROXY\` / \`DIRECT\`；Standard / Stable / Strict 在这里仅区分场景集合，不提供节点级地区组、同地区故障转移或固定节点。

因此，不应仅根据 Standard / Stable / Strict 名称推断某个接入方式具备节点级拓扑能力。

> 路由模式只控制 Hrules 的出口选择逻辑。它不能保证第三方服务不会触发风控、封号或地区资格限制。
